# CSS Overview remediation

## Baseline

The supplied Chrome CSS Overview capture reported:

- 9 contrast issues
- 15 background colors
- 10 text colors
- 3 fill colors
- 2 border colors
- approximately 30 ineffective `vertical-align` declarations
- unusual computed sizes of 7px and 27.2px, plus many 9px and 10px labels
- Inter and JetBrains Mono

The capture did not include the affected DOM nodes or the foreground/background
pairs for the nine contrast entries. Consequently, this remediation does not
claim a one-to-one DOM identification that the evidence cannot support. A fresh
CSS Overview capture is required to confirm the final browser count.

## Contrast and semantic colors

`app/globals.css` now exposes centralized `success`, `warning`, `critical`, and
`informational` color pairs through Tailwind's theme in addition to the existing
background, foreground, card, muted, primary, destructive, border, input, and
ring tokens.

The global muted foreground was strengthened without changing its neutral
meaning:

| Pair | WCAG contrast |
| --- | ---: |
| Light muted on card | 6.14:1 |
| Light muted on page | 5.67:1 |
| Dark muted on card | 8.26:1 |
| Dark muted on page | 9.23:1 |
| Light success badge | 4.57:1 |
| Light warning badge | 6.37:1 |
| Light critical badge | 6.80:1 |
| Light informational badge | 7.15:1 |
| Dark success text on card | 9.69:1 |
| Dark warning text on card | 11.71:1 |
| Dark critical text on card | 8.89:1 |
| Dark informational text on card | 9.36:1 |

Status components retain their textual labels and/or icons, so their meaning is
not conveyed by color alone. Brand, chart, authentication-image overlay, shadow,
and status colors remain intentional hard-coded palette definitions.

## Typography and line height

- Replaced all 459 source occurrences of `text-[7px]`, `text-[8px]`,
  `text-[9px]`, and `text-[10px]` with the existing `text-xs` (12px) design
  token.
- The 7px `Industrial IoT` sidebar label is now 12px.
- Compact table headings, badges, IDs, timestamps, metadata, and technical
  labels now meet the documented minimum.
- Existing 11px and larger values were retained where they are deliberate.
- Shared `Select` controls now use `text-sm`.
- Shared `Textarea` controls now use `text-sm` with `leading-5`.
- No source declaration uses a line height smaller than its font size.
- The reported 27.2px value is a computed result of the supported
  `html.large-interface-text` 112.5% scaling, not an accidental 27.2px source
  declaration, so it is retained.
- Inter remains the interface font; JetBrains Mono remains limited by existing
  `font-mono` usage to compact technical content.

## Vertical alignment

The required repository search returns zero occurrences of:

`vertical-align`, `align-middle`, `align-top`, `align-bottom`, or
`align-baseline` in `app`, `components`, and `lib`.

Therefore zero source declarations were removed. The approximately 30 entries in
the original Overview are generated by dependencies/browser styles rather than
these application sources. Removing unrelated flex/grid alignment would change
the approved layout and would not correct those generated declarations.

## Shared components

- `components/ui/select.tsx`: standardized text size, input border, focus-visible
  ring, and disabled state.
- `components/ui/textarea.tsx`: standardized text size and readable line height.
- Existing Button, Dialog, Card, Badge, Alert, Table, Tabs, Toast, Skeleton,
  empty-state, and error-state structures were retained to avoid redesigning
  application behavior.

## Media queries retained

- `max-width: 900px`: authentication layout switches from two columns to one and
  hides the decorative hero. It is component-specific and does not exactly
  duplicate a Tailwind breakpoint.
- `max-width: 560px`: authentication card/header/footer tuning prevents clipping
  on narrow phones. It is component-specific and does not exactly duplicate a
  Tailwind breakpoint.
- `prefers-reduced-motion`: retained as an accessibility requirement.
- Tailwind breakpoints and hover-capability queries: retained for responsive and
  input-capability behavior.

## Non-simple selectors retained

- `:focus-visible` and scoped focus selectors provide visible keyboard focus.
- `::placeholder` preserves readable form hints through the strengthened muted
  token.
- `.increase-contrast`, `.large-interface-text`, and `.reduce-motion` preserve
  user accessibility preferences.
- Scrollbar rules preserve the approved rail-free presentation while native
  wheel, touch, keyboard, and programmatic scrolling remain available.
- `a[href="/api-security/logs"]` is retained in this pass because changing the
  selector requires an application-component change unrelated to the measured
  contrast and typography issues.

## Remaining warnings and justification

- A fresh browser capture is needed to enumerate any remaining contrast entries
  because the supplied evidence omitted their DOM nodes and color pairs.
- Central palette hex/RGB values remain in `app/globals.css`; tokens need literal
  values at their definition site.
- Authentication artwork overlays, translucent shadows, chart series, and
  semantic status colors remain intentionally literal or token-backed.
- 11px and 13px component-specific values remain; neither matches the explicitly
  identified 7–10px failure range, and changing them globally would risk layout
  drift.
- The two custom authentication media queries are retained for their distinct
  layouts.
